# Exploration Envelope Canvas

## Purpose

Preserve low-friction AI exploration—including vibe coding—without allowing a
prototype to become an operated system by accident.

The discovery loop may begin with ambiguity. The production loop may not
conceal it.

## 4. Discovery record

- What became clearer:

- Which assumptions were contradicted:
- Which requirements emerged:
- Which questions remain unresolved:
- Which prototype behavior may be accidental or misleading:

## 5. Terminal disposition

Choose one:

- discard—the question was answered;
- extend the exploration with a new expiry and boundary;
- preserve only the learning record;
- submit an opportunity brief for portfolio admission;
- begin production translation after explicit admission.

## 6. Production translation gate

Before any reuse, identify:

- authoritative outcome and stakeholder;
- prohibitions and value conflicts;
- production owner and consequence owner;
- architecture and integration constraints;
- security, privacy, accessibility, and regulatory requirements;
- independent evidence floor;
- release, recovery, support, and retirement obligations;
- prototype code that will be discarded, rewritten, or evaluated as a new
  candidate.

A successful demo is evidence of possibility. It is not evidence of readiness.

## Worked fictional example

Alder & Finch uses vibe coding to explore an internal contract-comparison tool.
The prototype uses synthetic contracts in an isolated workspace and expires in
fourteen days. It reveals that clause extraction is feasible but that users
disagree about which differences are material. The team preserves screenshots,
questions, and evaluation examples, then deletes the prototype. A product agent
prepares an opportunity brief; legal and procurement owners decide whether a
bounded advisory capability deserves admission. No prototype code reaches the
production Work Order automatically.
