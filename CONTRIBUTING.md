# Contributing

Corrections, clearer failure cases, portability improvements, and additional
tests for published invariants are welcome.

Contributions must:

- remain vendor-neutral unless a vendor-specific example is explicitly labeled;
- distinguish implemented behavior from a proposed design;
- include failure and stopping behavior, not only a happy path;
- contain no credentials, private prompts, customer data, protected paths,
  confidential implementation material, or unverifiable performance claims;
- preserve the repository's code/content license boundary.

Open an issue before proposing a material architectural change. A pull request
should state the promise it protects, the failure it exposes, the evidence used
to verify it, and the compatibility impact.
