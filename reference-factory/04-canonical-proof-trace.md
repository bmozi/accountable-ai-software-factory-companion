# Canonical Proof Trace: The Meridian Ledger Update

**Case status:** fictional composite for instruction; not evidence of a real
deployment or measured result

Meridian Ledger operates an internal scheduling service. A library used to parse
uploaded calendar files has a supported patch release containing a security
fix. The work is frequent and usually reversible, making it a plausible first
factory work class. The service also has a fragile import path used by one
regional operations team.

## 1. Intent and ambiguity

The request says, “Apply the safe update this week.” Admission refuses the word
“safe” as an acceptance criterion. The work-class owner clarifies the promise:
upgrade only the patch version, preserve import behavior, introduce no new
network destinations, and release initially to ten percent of internal traffic.
The countermetric is import failure for the regional file format.

## 2. Durable admission

Work Order version 1 records criteria, prohibited effects, baseline, exposure,
rollback owner, resource and cost budgets, and a forty-eight-hour observation
window. The evidence owner requires dependency resolution, unit and integration
tests, vulnerability policy, license policy, and a human review of the fragile
format. A request to update an unrelated framework is explicitly out of scope.

## 3. Bounded execution

One execution owner receives repository-scoped read and candidate-write
authority. It cannot merge, deploy, change evidence policy, or read production
secrets. The first attempt discovers that the lockfile would also change a
transitive package outside the admitted range and stops. The owner updates the
Work Order to version 2 after the consequence owner accepts that bounded change.

## 4. Candidate and disputed evidence

Attempt 2 creates candidate digest C2. Unit tests and ordinary imports pass.
The security and license criteria pass. The regional-format test fails because
the fixture contains an undocumented encoding variant. The producer argues
that the fixture is obsolete; the evidence plane records the criterion as
failed rather than converting that explanation into a pass.

A domain reviewer confirms that the format still arrives weekly. The decision
owner returns **revise**. Attempt 3 adds a narrow compatibility correction and
produces digest C3. Every prior artifact-bound verdict is invalidated. The full
evidence set reruns; the regional test now passes, while the reviewer records a
limitation: only six historical samples were available.

## 5. Release and interruption

The release authority approves ten-percent exposure under the recorded policy.
The delivery worker loses its response after requesting the rollout. The
receipt remains indeterminate. Restart reconciliation inspects the target and
finds one rollout with the expected operation identifier already active. It
records completion rather than issuing a second rollout.

## 6. Mixed outcome

During forty-eight hours, the vulnerable version disappears and ordinary import
latency is unchanged. The regional-format failure rate rises slightly but the
sample is too small to distinguish change from ordinary variation. The primary
technical result is favorable; the countermetric is **insufficient evidence**.
The outcome owner continues bounded exposure for another preauthorized window
without widening it.

The extended window confirms a small regression. The outcome disposition is
**harmful for the declared scope**, even though all pre-release criteria passed.
The rollback owner restores the prior version while a repaired candidate is
prepared. This is not a failed evidence system: runtime observation discovered
a limitation the small historical test set could not establish.

## 7. Governed learning

The factory proposes, “Require twenty regional-format samples for every
dependency update.” The learning authority rejects the universal rule because
most services never process that format. It admits a narrower, expiring rule:
services declaring the regional-import capability require a representative
sample threshold or an explicit insufficient-evidence release plan. A follow-up
experiment will measure recurrence and review burden over ten eligible updates.

The proposal cannot edit release policy, its own evaluation criteria, or its
expiry. A named control owner retains those decisions.

## What this trace teaches

The factory created value even though its first released candidate was rolled
back. It refused ambiguous intent, preserved scope change, kept production and
evidence distinct, survived an uncertain effect, treated a countermetric as a
real constraint, and narrowed a learning instead of universalizing it. Those
are capabilities a coding demonstration does not reveal.
