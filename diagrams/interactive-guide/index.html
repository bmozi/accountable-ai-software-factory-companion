A failure you can explain

Change one fact. Reconsider the decision.

Fixed fictional examples illustrate the boundary. They do not execute the laboratory or evaluate real policy.

Conceptual decision record

Stale advice must be refreshed

What changed
The source moved from version 1 to version 2. The advice still names version 1.
Safe next action
Stop dependent use, inspect the correction and evaluate a newly derived view.
Evidence to retain
Old and current source versions, recorded derivation, the blocked-use decision and the refreshed-view decision.

This protects recorded dependencies. It does not discover omitted ancestry or prove the source is true.

Explain autonomy carefully

Describe the assistance. Specify the permission.

These five proposed descriptions explain human involvement. They are not credentials, risk tiers or an automatic escalation ladder.

Five descriptive assistance levels; every effect still needs current authority
LevelAssistanceBoundary to explain
0ObserveRead permitted information. Reading still requires access.
1RecommendPropose an action without permission to perform that action.
2PrepareCreate a scoped draft or patch. Writing that draft is itself an effect.
3Execute with approvalPerform the precise approved action after current checks.
4Execute within explicit delegationStay within named resources, actions, time and budget. Revocation still applies.

An agent inventory, evaluated version or tool description can help discovery and review. None grants permission. Integrations must preserve the receiving system’s identity, effect and recovery contracts.

What this experience establishes

This is a public, vendor-neutral teaching guide for selected accountability responsibilities. The browser examples are fixed illustrations. The Python extension is a separate small teaching mechanism; its tests do not establish production authorization, enterprise connector coverage, distributed concurrency, regulatory compliance or business benefit.

Choose a factory pattern only when the work and consequence justify it. Keep one integrating owner, independent evidence and a supported way to stop or recover. A reusable factory-line description can organize these responsibilities without becoming a new permission authority or an arbitrary workflow engine.
