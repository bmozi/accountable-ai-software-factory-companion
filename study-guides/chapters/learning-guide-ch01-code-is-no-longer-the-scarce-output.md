# Learning Guide — Chapter 1: Code Is No Longer the Scarce Output

> **Learning Objectives** — After completing this chapter, you will be able to:
>
> 1. Explain why faster code generation shifts constraints elsewhere in delivery.
> 2. Analyze a change from request through observed outcome.
> 3. Distinguish machine activity from customer and organizational value.
> 4. Construct a constraint map for one real delivery flow.

## Study Guide

### Key Terms

- **Constraint:** The step that limits the flow of useful, trustworthy change.
- **Candidate:** A generated change that has not yet earned release.
- **Queue time:** Elapsed time spent waiting for a decision or capability.
- **Outcome:** An observed change in a customer, system, or organization.
- **Rework:** Effort required to correct or repeat prior work.

### Review Questions

1. Why can faster generation increase review risk?
2. Which outputs remain scarce when code becomes abundant?
3. Why is a technically strong diff not evidence of value?
4. What information belongs in a constraint map?

### Discussion Questions

1. When might reducing generated output improve delivery performance?
2. Which local productivity metric is most likely to conceal displaced work in your organization?

### Exercises

**Exercise 1.1 (Core): Trace one change.** Reconstruct a change from request to observed outcome and separate active time, queue time, and rework.
*Deliverable:* A completed constraint map.
*Assessment:* Every material transition has a duration, owner, and evidence source.

**Exercise 1.2 (Core): Challenge an activity metric.** Select one AI activity metric and identify the outcome it is assumed to predict and the burdens it may move elsewhere.
*Deliverable:* A metric-and-countermetric note.
*Assessment:* The note distinguishes observation from inference and names a countermetric.

**Exercise 1.3 (Challenge): Redesign the bottleneck.** Propose a bounded intervention at the current constraint without increasing downstream risk.
*Deliverable:* A one-page intervention hypothesis.
*Assessment:* The hypothesis states baseline, expected outcome, countermetric, owner, and stop rule.
