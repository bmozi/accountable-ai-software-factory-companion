# External Reader Usability Pass

## Status

Recruitment is open for companion release **v1.2.0**. Automated and
cross-platform checks run in CI; those checks are not represented as human
reader evidence.

## Purpose

Determine whether a new reader can run the minimum laboratory, connect a
failure to the responsibility it protects, change one bounded contract, and
leave with a reviewable decision artifact without coaching.

## Small-pass protocol

Recruit three to five readers who resemble the intended audience. Include at
least one practicing software engineer and one engineering leader or
architect. Include one Windows reader and, when available, one reader who
routinely uses keyboard navigation, text reflow, magnification, or a screen
reader.

Do not introduce the repository beyond this sentence: “Use this laboratory to
build, break, and inspect one minimum accountable AI software factory.” Then
ask each reader to perform these tasks:

1. Find the prerequisites and run the documented reader journey.
2. Identify one failed path and explain the promise it protects.
3. Locate the contract or policy that governs that path.
4. Change one reversible criterion, prohibition, budget, or authority rule and
   identify the test that should fail first.
5. Produce or locate one decision artifact another operator could inspect.
6. Explain why the laboratory is not a production starter kit or safety claim.
7. Find how to report a broken resource, correction, security concern, or
   accessibility barrier.

Record environment, completion, elapsed time, wrong turns, commands, questions,
and the reader's own words. Do not repair the environment or explain the
architecture until a task has clearly failed.

## Pass criteria

- At least four of five readers, or all three in a three-reader pass, start the
  documented journey within five minutes after prerequisites are available.
- At least 80 percent of tasks are completed without coaching.
- Every reader can connect a passing or failing check to a responsibility and
  a human disposition, not merely to green code.
- The Windows reader completes the documented native or Git Bash/WSL path.
- No critical accessibility barrier prevents navigation or issue reporting.
- Every repeated wrong turn becomes an issue with an owner and disposition.

Submit one issue per participant using the
[reader-usability form](https://github.com/bmozi/accountable-ai-software-factory-companion/issues/new?template=reader-usability.yml).
Aggregate conclusions only after the small pass is complete; do not average
away a severe failure.
