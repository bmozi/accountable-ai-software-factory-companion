# Optional copy of the printed lesson

The book's appendix **One Factory, From Request to Outcome** contains both
Python files in full, instructions, a worked paper case, chapter practice facts,
and a different-domain transfer exercise. That core route requires no repository.
These files save retyping; the larger `reference-factory` laboratory remains an
optional extension with additional mechanisms.

From this directory run:

```sh
python3 -m unittest -v test_paper_factory.py
```

Expected: 10 tests pass. Python 3 with standard-library SQLite is required;
there are no downloads, model calls, Git effects, or accounts in this lesson.
Tests create temporary local databases and clean up only their own files.

The printed program admits a sandbox **rounding configuration**, tests a single
decimal fixture, records disposition, and demonstrates target acceptance with a
lost reply and reconciliation across two durable stores. It is separate from
the book's expanded **parser patch paper case** and from the larger companion's
reference journey. Their counts, thresholds and implementation scope must not
be combined as if they were one measured experiment.

Role strings are simulated permissions. There is no production identity or
security isolation, real software deployment, automatic rollback, statistical
outcome proof, or governed learning promotion. The target stores an accepted
configuration; observation uses synthetic counts. The book explains the wider
responsibilities that remain. Passing these tests establishes only the selected
local mechanisms.
